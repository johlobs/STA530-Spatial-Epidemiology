# STA530 — Interactive Study App

## Project
Quarto + WebR study reference and exam-prep tracker for STA530 Spatial Epidemiology (University of Gothenburg, autumn 2026, 1 Oct – 3 Nov; teacher Qinyun Lin). Built with the STA520 app as the template. The course adds material session by session; add new sessions as new pages, do not rewrite existing ones.

- **Source**: `C:/Users/nepet/Documents/Studier/Masterprogram i tillämpad biostatistik/STA530 Spatial Epidemiology/App/`
- **Course material**: the parent folder (`session_N_*.pdf`, `Posts on class page.docx` = Canvas posts with objectives and key questions, `Notes.docx` = lecture notes, syllabus, literature list)
- **Stack**: Quarto website, knitr engine (every session page sets `engine: knitr`), WebR for `{webr-r}` cells (base R only), plain JS includes.
- **Exam**: written exam tests concepts, not programming (lecture notes). Seminar 1 hp.

## Pages
- `session1.qmd` … `session4.qmd`: one page per session (scanned by `build_topics.py`)
- `dashboard.qmd`, `exam-practice.qmd` (drills + written questions W1…, instructor questions marked [instructor]), `glossary.qmd`, `about.qmd`, `index.qmd`

## Topic sections (drive the checklist and dashboard)
Every checklist item is a level-2 heading in a session file:

```markdown
## 2.11 Global Moran's I {#t2-11 .topic flag="objective"}
```

Flags: `objective` 🎯 (syllabus / Canvas objectives / "Learning goals" slide), `keyq` ❓ (instructor key question or slide question), `notes` ✏️ (in the lecture notes), `inferred` 📌 (AI-inferred), `optional` 📎 (instructor: optional or out of scope), `seminar` (reserved). IDs must stay stable (localStorage key `sta530_topic_status`).

Adding a session: create `sessionN.qmd`, add it to `_quarto.yml` sidebar and `index.qmd`, add its title to `LECTURE_TITLES` in `_topics.html`, update `about.qmd` (sessions table). Cross-session pages go in `EXTRA_PAGES` in `build_topics.py`.

## Includes (after body)
- `_topics-data.html` generated by `build_topics.py` (pre-render). Do not edit by hand.
- `_topics.html` status buttons, badges, sidebar counters, dashboard
- `_quiz.html` + `_quiz-filter.lua` quizzes (`:::: {.quiz}`, bold = correct, `::: {.exp}` explanation)
- `_drills.html` randomised drills: `<div class="drill" data-drill="NAME"></div>`, names: `smr, smrstd, eb, boxmap, neighbours, moran, sarimpact, logrr, likelihood, exceed`

## Figures
- Static figures are base-R chunks (`echo: false`, label `fig-NAME`) that simulate made-up data. Shared helpers (grid weights, Moran's I, `draw_grid`, `box_node`, `bottom_legend`, colours) live in `_helpers.R`, sourced by a hidden setup chunk at the top of each session page.
- Prefer side-by-side panels for comparisons. Avoid Mermaid subgraphs: they render with a dark fill; draw such diagrams in R instead.

## Writing rules
- English content; define abbreviations on first use per page.
- Each session starts with intro, "Sources and session" and "Before you start" callouts. Misconceptions go in `::: {.misconception}` boxes. Method sections get "When to use" / "Limitations" callouts where useful.
- Quiz options roughly equal length; the correct one must not stand out.
- Flow diagrams: caption starts with Causal diagram / Workflow / Lecture map.
- Labs: concepts on made-up data only, never lab solutions (public site).
